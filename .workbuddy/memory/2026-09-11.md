## 关键设计结论（后续复用）
- 状态根 `GARMIN_STATE_DIR` 与 session 文件解耦：`state/<accountKey>/operations.json`，目录 0700 / 文件 0600。
- 业务键：`schedule` = accountKey + workoutId + localDate（**时区不进入**，否则换时区就能绕过）；幂等键单独哈希，不混用。
- 硬阻塞状态只有 `in_flight` / `unknown`；`prepared` 可被新预览取代，`succeeded`/`skipped` 不阻塞（靠新鲜预检），`failed`/`not_attempted` 允许重试。
- `in_flight` **先落盘再发包**；落盘失败则不发。执行时只派发 `prepared` 步骤 → 被取代的旧预览永远无法补写。
- 锁：`mkdir` 原子独占 + ownerToken；**无 TTL 抢占**；非 owner 不可释放。等待上限默认 5s → `OPERATION_BUSY`。

## 环境坑（重要）
- **沙箱会把 `mkdir` 的 `EEXIST` 改写成 `CODEBUDDY_BROKER_DENY`**。因此锁的争用判定改成「错误码 OR lstat 证据」，不依赖单一错误码。
- `npm run build` 在本沙箱**必然失败**：`scripts/clean.mjs` 触发 bulk-delete 守卫（140 > 50）。用 `npx tsc` 代替。
- 跑测试要 `NODE_OPTIONS=""`，否则 `browser-auth-canary-runtime` 会因为沙箱注入的 `--require` 判为「弱化 HTTP 策略」而失败（非真实回归）。
- `npm run pack:smoke` / `test:distribution` 需要 `npm_execpath`；直接跑脚本时手动导出它。
- `StdioClientTransport` 会**清洗子进程环境变量**：子进程拿不到 `GARMIN_STATE_DIR`，必须在测试里显式传 `env`。
- 同一文件**不要并行 Edit**（会丢改动），改为串行。
